# Master prompt — 3 шинэ бичлэгийн туршилт ба зурагт GitHub тайлан

Чи миний Linux компьютер дээр ажиллах Codex хөгжүүлэгч. Ажлын хавтас `/home/jinlight/Documents/TDB`. GitHub төсөл `JinLight0818/cv-tracking-optical-flow-lab`. Миний бэлдсэн гурван видеог одоо байгаа OpenCV төслөөр **бодитоор ажиллуул**. Алгоритмуудыг ижил нөхцөлд хэмжиж, дүгнэлт, зураг, графиктай **бүрэн тайланг repository-ийн `README.md` дотор** бич. README-г GitHub дээр нээхэд эхнээс нь дарааллаар уншаад ажлын зорилго, аргууд, туршилт, үр дүн, хязгаарлалтыг ойлгодог байг. Ажлын төгсгөлд өөрчлөлтүүдээ GitHub-д push хийж, гарсан README-г баталгаажуул.

Ажилладаг хэрэгслүүдээ дахин ашигла. GitHub-ийн шинэчлэлийн суурь болгож одоогийн `origin/main`-ийг шалга. Одоо байгаа локал ажлыг хадгалж, шаардлагатай бол тусдаа branch эсвэл worktree ашигла.

Аль нэг нь олдохгүй бол олдсон хэсгээ гүйцээж, байхгүй файлыг яг нэрээр нь мэдэгд.
- Кадрыг нүдээр шалгаад **аль объектыг дагаснаа** тодорхой бич. Бичлэг бүрийн урт, өргөн × өндөр, FPS эсвэл кадрын бодит хугацаа, камерын хөдөлгөөн, ашигласан үргэлжилсэн кадрын муж, эх үүсвэрийг бүртгэ. Үүсмэл анимейшн, гаднын эх сурвалж, өөрийн камераар авсан материалын аль болохыг баталгаатай үед нь тэмдэглэ. Халхлалтын файл өмнө үүсгэсэн анимейшнтэй ижил эсэхийг файлын нэрээр бүү таа. Халхлагдсан хугацааг энэ видеогоос шинээр шалга.
- Бичлэг урт эсвэл эвлүүлэгтэй бол объект тод харагдах эхлэл, үйл явдлын өмнөх ба дараах хэсэг орсон богино, үргэлжилсэн тайрдас сонго. **Tracker-ийн оноог харахаас өмнө** кадрын мужийг тогтоо. Эх кадрын дугаар, тайрдасны доторх дугаар, хугацааг хадгал. `custom_video_lab.py`-ийн одоогийн 300 кадрын хязгаарт үйл явдал багтах эсэхийг шалга. Хэрэв тайрдас ашигласан бол README-д яг ямар хэсгийг хэмжсэнийг бич.

## 2. Шошгололт ба хэмжилт

### Объект дагах

1. Эхний тод харагдах кадрт нэг объектын хүрээг гараар тогтоо. Ижил кадр, ижил анхны хүрээг `STATIC`, `BOOSTING`, `MIL`, `KCF`, `TLD`, `MEDIANFLOW`, `CSRT`, `CSRT_REDETECT`-д өг. Эхлэх кадрыг оноонд оруулахгүй. Боломжтой бол объектын **харагдах хэсгийн хүрээ** гэсэн нэг дүрмийг бүх бичлэгт баримтал.
2. Шалгах хэсгийн кадр бүрд шошго үүсгэ. Тогтвортой хэсэгт завсрын хүрээг интерполяц хийж болно. Халхлах, дахин харагдах, дүрс тасрах болон чиглэл огцом солих орчимд кадр бүрийг нүдээр шалга. Одоогийн `--annotate --step 5` нь хоёр түлхүүр кадрын аль нэг нь хоосон бол дундах кадруудыг бүгдийг алга гэж тэмдэглэдэг. Ийм заагт `--step 1` эсвэл нарийн шошго ашигла. `GT байхгүй`, `түр харагдахгүй`, `харагдаж байна` гэсэн төлвүүдийг шаардлагатай үед тодорхой ялга. Видео ба CSV зөрвөл богиносгож чимээгүй тааруулахын оронд кадрын ID ба мөрийн тоог шалга.
3. Нэг кадрын хүрээний давхцлыг **IoU**-аар хэмж. Бичлэг тус бүрд дундаж IoU, IoU ≥ 0.5-тай кадрын хувь, эвдрэлийн хувь, үнэлсэн кадрын тоог тайлагна. Объект харагдахгүй үед гарсан буруу хүрээг **n/N кадр** гэж бич. Ийм кадр байхгүй бол `N/A`. Tracker объект андуурсан бол дараалсан кадрын тоог **тохиолдлын тоо** гэж бичихээс зайлсхий.
4. Халхлалтын бичлэг дээр объект анх буцаж харагдах кадрыг гараар тогтоо. **IoU ≥ 0.5 гурван кадр дараалан** хангасан бол тухайн цувралын эхлэл ба баталгаажсан гурав дахь кадрыг хоёуланг нь тайлагна. Дахин олоогүй аргыг тусгайлан тэмдэглэ. Сурагчдад ойлгуулахын тулд «объект алга байхад tracker зөв зогссон уу» ба «гарч ирэхэд эргэж олсон уу» гэсэн хоёр асуултад тусад нь хариул.
5. Одоо байгаа benchmark-ийн тохиргоог ашиглан нэг урсгал, ижил нягтрал, ижил оролтоор алгоритмын медиан болон p95 ms/frame-ийг боломжтой үед гарга. Кадр унших, дүрслэх зэргийг хамруулсан хугацааг тусад нь нэрлэ. Кадр бүрийн үр дүн, шошго ба товч дүнг CSV-д хадгал. README-ийн тоог CSV-тэй тулга. Эвдэрсэн аргыг ажилласан мэт тайлагнахгүй.

### Optical flow ба камерын хөдөлгөөн

- **Stable** дээр LK-ийн сонгосон цэгийн мөр, Farnebäck эсвэл DIS-ийн хөдөлгөөний зургийг нэг ижил хос кадраар харьцуул. Тогтвортой байхаар сонгосон арын хэсэгт хөдөлгөөний хэмжээ бага эсэхийг шалга.
- **Moving camera** дээр эх кадр, нягт flow, камерын ерөнхий хөдөлгөөнийг хассаны дараах flow-г ижил масштаб, ижил кадраар зэрэгцүүл. Одоогийн FB-LK + RANSAC нөхөлтийг ашигла. Боломжтой бол объект ба дэвсгэр дэх медиан хөдөлгөөн, дэвсгэрийн хөдөлгөөн хэдэн хувиар буурсныг тусад нь хэмж. Камерын хөдөлгөөн арын хэсгийн цэгээр сайн илэрхийлэгдсэн эсэхийг шалга. Нөхөлт амжилтгүй кадр гарвал зурагт нэг бодит жишээ оруул.
- Видео бүрийн пикселийн бодит хөдөлгөөний шошго байхгүй бол түүнийг ил тод бич. **EPE гаргахын тулд бодит хөдөлгөөний вектор шаардлагатай.** Эдгээр бичлэгт камерын нөхөлтийн үлдэгдэл хэмжээ, цэг хадгалалтын хувь, харагдах дүрслэлийг хэмжиж болно. IoU-г объектын хүрээтэй, EPE-г урсгалын шошготой өмнөх benchmark-уудтай нь холбо.

## 3. README-г зурагт тайлан болго

README-г **монгол хэлээр** бич. Англи нэр томьёог анх гарахад нэг өгүүлбэрээр тайлбарла. Төслийн өмнөх PDF давталт, OpenCV аргууд, бодит ба хяналттай датасетийн баталгаажсан дүн, эх сурвалжуудыг хадгалж, шинэ гурван видеоны үр дүнтэй уялдуул. Гол тайлбарыг дээр, суулгалт ба ажиллуулах командыг доор тавь.

1. **Товч хураангуй ба нээлтийн зураг.** Гурван бичлэгээс нэг нэг төлөөлөх кадр сонгон нэг мөрт зураг хий. Доор нь туршилтаас үнэхээр гарсан 2–3 гол дүгнэлтийг тоотой бич.
2. **Зорилго ба үндсэн ойлголт.** Tracker-ийн хүрээ, LK-ийн цэгүүд, dense flow-ийн сум эсвэл үргэлжилсэн өнгөт зургыг нэг жишээгээр тайлбарла. IoU-д жишээ болгож нийлсэн талбай 100, давхцсан талбай 60 бол IoU 0.60 гэдгийг харуул.
3. **Өгөгдөл ба аргачлал.** Эх үүсвэр, объект, туршсан кадр, шошгололт, алгоритмууд, хэмжилтийн нөхцөлийг хүснэгтээр бич. PDF-ийн давталт, өмнөх benchmark, шинэ бичлэгийн сорилын аль болохыг уншигч ялгаж хараг.
4. **Үр дүн.** Гурван бичлэгийн гол үзүүлэлтийг харьцуулсан хүснэгт, алгоритмын бүрэн CSV рүү холбоос, доорх зурагтай хэсгүүдийг оруул.
   - `stable_tracking.png` — нэг кадрт бодит хүрээ ба tracker-ийн хүрээ. Хажууд LK-ийн цэгүүдийг харуул.
   - `moving_camera_flow.png` — эх кадр, камерын хөдөлгөөнтэй flow, нөхөлтийн дараах flow. Өнгө, сумны чиглэл ба масштабыг тайлбарла.
   - `occlusion_storyboard.png` — **харагдаж байна → хэсэгчлэн халхлагдсан → бүрэн алга → дахин гарсан** гэсэн кадрууд. Кадрын дугаар, GT, сонгосон 2–3 tracker-ийн амжилт/алдааг тэмдэглэ.
   - `occlusion_iou_timeline.png` — кадр тус бүрийн IoU, халхлалтын зурвас, дахин харагдсан ба сэргэлт батлагдсан кадрууд. GT-гүй үеийг графикт ялгаж харуул.
   - `video_benchmark_comparison.png` — гурван бичлэгийн IoU ба алгоритмын хугацаа. Сорил бүрийн тоог үзүүлж, STATIC-ийн хугацааг ердийн tracker-ийн хурдтай нэг баганад эрэмбэлэхээс зайлсхий.
5. **Алгоритмын тайлбар ба дүгнэлт.** «Аль арга энэ нөхцөлд яагаад алдсан бэ» гэдгийг алгоритмын зарчим болон нэг бодит кадраар тайлбарла. **Баталгаажсан үр дүн**, **боломжит шалтгаан**, **хязгаарлалт** гэсэн гурван санааг ойлгомжтой бич. Шинээр нэмсэн `CSRT_REDETECT`-ийг энгийн CSRT ба TLD-тэй харьцуул. Бүх видеонд нэг ялагч зарлахын өмнө бичлэг тус бүрийн ялгааг шалга.
6. **Дахин ажиллуулах.** Суулгалт, файлуудыг байрлуулах, шошголох, benchmark, зураг үүсгэх, тестийн бодитоор шалгасан командыг оруул. Ашигласан орчин, commit, өгөгдлийн эх сурвалж, зураг бүрийн тайлбарыг үлдээ.

Зургуудыг `results/figures/custom_videos/` зэрэг тогтвортой замд хадгалж, README-д **харьцангуй замтай Markdown зураг** болгон оруул. Alt text, кадрын тайлбар, өнгөний тайлбар нэм. Гар утсан дээр уншигдах хэмжээг сонго. Тайлангийн хэмжилтэд орсон зургийг туршилтаас гарга. Нийтлэх эрх нь тодорхойгүй видеоны кадрын оронд тухайн гүйлтээс гарсан график, эх дүрсгүй хүрээний схемийг ашиглаж болно.

**Нэмэлт санаа.** Халхлалтаас гарах үеийн нэг кадрыг «яагаад алдав» гэсэн богино зурагт тайлбар болго. Жишээ нь шинэ CSRT саадтай төстэй объект руу шилжсэн эсвэл анхны загвар нь эргэсэн биеттэй тохирохгүй болсон кадрыг сонго. Боломжтой бол төсөөтэй объектын андуурал болон камерын хөдөлгөөн нөхөхийн өмнөх/дараах ялгааг нэг жижиг хүснэгт, нэг зурагт үзүүл. Дүгнэлт бичихэд хэмжилт хүрэлцэхгүй бол ажиглалт гэж тэмдэглэ.

## 4. Баталгаажуулж GitHub-д оруул

- Гурван тайрдас бүрийг уншиж чадаж байгаа эсэх, CSV дахь кадрын дугаар ба шошго яг таарч байгаа эсэх, зурагт үзүүлсэн кадр тайлбартайгаа тохирч байгаа эсэхийг шалга. Тайлангийн тоонууд, гол зураг, харьцангуй холбоосуудыг тус бүрээр тулга. Одоогийн unit тест ба шинэ видео ажлын богино гүйлгээг ажиллуул. README-ийн холбоос, зураг GitHub дээр ачаалагдахыг шалга.
- **Repo-д оруулах зүйлс** нь README, шаардлагатай кодын өөрчлөлт, ажиллуулах заавар, хэмжилтийн CSV, нийтлэх эрхтэй тайлангийн зураг, сонгосон жижиг хэмжээний зөвшөөрөгдсөн демо. Гурван эх MP4-г локалд байлга. Сургалтын PDF, түүхий датасет, хувийн замтай лог, нэвтрэх мэдээлэл, бусад төслийн файлыг stage хийхээс хамгаал. Эх сурвалж эсвэл ашиглах зөвшөөрөл шаардлагатай бол `NOTICE.md`-ийг шинэчил.
- Өөрчлөлтөө тусдаа салбарт commit хийж **`JinLight0818/cv-tracking-optical-flow-lab`** руу push хий. Repo-ийн зөвшөөрөгдсөн урсгалаар үндсэн салбар дээр README-г гарга. Шууд нэгтгэх эрх байхгүй бол тухайн branch-ийн README ба PR холбоосыг өг. Force push ашиглахгүй. Эцэст нь алсын commit SHA болон README-д зургууд ачаалагдахыг баталгаажуул.

Эцсийн хариуг монголоор товч бич. Гурван бичлэг тус бүрийн гүйлгээний төлөв, гол хэмжилт, тод үлдсэн хязгаарлалт, GitHub-ийн README болон commit холбоосыг өг. Видео файл байхгүй үед бэлэн үр дүн зохиохгүй. Боломжтой хэсгийг дуусгаад, яг ямар файл дутсаныг мэдэгд.
